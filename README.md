# TYCPHIGROS4.0.1.2

音频更新 `4.0.1.2-input-10`：12 首内置歌曲与开场音乐加入 24 kbps 双声道 OGG/Opus 省流音轨，平均比原歌曲小约 80%。弱网、节省流量模式和未知线路优先使用小音轨；强网优先使用原始音轨。浏览器缺少网络信息接口时，依据本站资源的实际下载速度判断，尚无测量时保守使用省流版。若强网估计偏乐观且大音轨的下载速度持续很低，自动切换省流版并继续加载，不显示超时错误。浏览器不能播放 OGG/Opus 时使用 32 kbps AAC 省流备选。切换只发生在开歌前，播放中不更换音轨。当前仓库原始歌曲是 Vorbis OGG，已经有损，没有真正的 FLAC/无损源；强网保留现有原始质量，不将有损转码伪称无损。全部 26 个新增音轨已完整解码并核对双声道及全曲时长。

输入与加载修复 `4.0.1.2-input-9`，处理 iPad 快速连点吃键、国内弱网材质加载失败与音画延迟。

在 iPad/iPhone（包括桌面 UA 的 iPad Safari）启用原生 TouchEvent 单一判定源，PointerEvent 的触摸回声不再参与判定。旧版同时接受两套事件，再用 12ms / 6px 匹配；两套事件偏差超过阈值时，一次按下可能消耗两个相邻蓝键。新增回归覆盖偏移 20ms / 10px 的回声、十次连续蓝键、以及先从另一根手指快照补收、后收到 touchstart 的同一触点。鼠标、笔与其他浏览器的兼容路径保留。真实 iPad 的快速双指与持续帧率仍需现场验证，模拟测试不能替代真机。

移除内置材质整体 20 秒、资源读取 45 秒及谱面 Worker 的 30–45 秒硬截止。内置皮肤、音乐与噪域贴图解码也不因固定时长被跳过。下载有进展或暂时没有响应时继续等待；网络连接中断、HTTP 408/429/5xx 自动重试，间隔逐步增加至最多 8 秒，不设重试次数上限。用户返回选歌仍可取消当前歌曲。404、非法分块范围或实际文件损坏仍报告具体错误，避免把错误资源当作成功。

`js/resource-transfer.js` 在主页面及谱面 Worker 中共用。大文件先请求有用的第一块，服务器支持 Range 时按 256 KiB 分块，单文件最多 3 块并发，单运行环境最多 4 个在途请求；谱面 Worker 与主页面独立工作。失败只重传当前块，已成功块保留；服务器不支持 Range 时使用一次完整响应。没有额外 HEAD 探测，没有第三方代理或 CDN。主页面同一资源的多个订阅者共享下载，取消封面不会中断其他调用者仍需使用的资源。完整资源组装校验后写入既有媒体缓存，206 响应不冒充完整资源。后台缓存写入不阻塞开歌。

内置音乐完整下载到本地 Blob 后才准备播放，优先解码至 Web Audio，使谱面直接跟随音频时钟；Web Audio 不可用时由本地 Blob 媒体元素播放。游玩期间无需继续依赖歌曲下载。这会增加弱网首次开歌前的等待与解码内存，换取整首音乐就绪后再开始；加载页显示实际下载百分比。原始 OGG、高清曲绘、完整皮肤与视频导出资源继续保留。分块并发能减少部分连接等待，但不会增加线路本身的带宽，GitHub Pages 国内直连的可达性仍取决于实际网络。

设置中的“输入与帧率详情”显示修复版本、当前输入源、实际点按数、蓝键/长条命中、无候选、噪域阻挡及最大事件派发延迟。使用 Web Audio 时直接报告本地音频后端，避免把已停用媒体元素的时间错误显示成音画延迟。绘制仍跟随 requestAnimationFrame，真实帧率不伪装成 120Hz；布局、噪域规则、判定窗口与视频导出分辨率不变。

入口和代码缓存更新到 `input-9`，媒体复用旧缓存。兼容旧入口缺少新传输组件的情况。验证命令：`node --test tests/*.test.cjs`。包含实际 Engine 方法的多指、编号复用、长按、噪域、音频时钟及帧率测试；全部 42 个 LZMA 资源在真实 Worker 中解码后与原 JSON 哈希一致；新增分块组装、失败块重试、持续慢响应、七次临时失败后恢复、HTTP 压缩长度、并发上限、取消、共享下载及完整本地音乐准备测试。尚未进行中国大陆网络或 iPad Safari 真机测试。

本项目由用户提供的 `Phi_SEKAI_视频导出最终版(2).html` 拆分而来。

保留原有界面、游戏逻辑、12 首内置歌曲（46 个难度谱面）、曲绘、原始皮肤和视频导出代码。网页通过同站相对路径读取资源，不依赖第三方 CDN。首次加载资源需要联网。

## 上传 GitHub 并发布

1. 解压本 ZIP。打开文件夹，应该直接看到 `index.html`、`assets`、`css`、`js`、`workers` 和本说明。
2. 登录 <https://github.com>，打开 <https://github.com/new>。
3. 仓库名称填写 `phi-sekai`，选择 **Public**，勾选 **Add README**，点击 **Create repository**。
4. 进入仓库的 **Code** 页面，选择 **Add file → Upload files**。
5. 上传解压后的项目内容，保持所有子文件夹的原有层级。不要只上传 ZIP，也不要额外套一层项目文件夹。应在仓库首页直接看到 `index.html`。
6. 点击 **Commit changes**。如果显示超过上传数量限制，可以分两次上传 `assets` 和其余文件，保持路径不变。
7. 在仓库进入 **Settings → Pages**，将 **Source** 设为 **Deploy from a branch**，**Branch** 设为 **main**，文件夹设为 **/ (root)**，点击 **Save**。
8. 等待部署完成，在 Pages 中点击 **Visit site**。项目网址一般为 `https://你的用户名.github.io/phi-sekai/`。
9. 学校电脑打开这个 Pages 网址即可；仓库地址是代码管理页，不能代替游戏网址。学校网络是否允许访问，需要现场测试。

GitHub 网页上传限制是每个文件 25 MiB。本项目的所有文件均低于该限制；上传前不需要再次压缩或拆分。

如果已经授权 ChatGPT 的 GitHub 插件访问该仓库，可以把仓库链接发给 ChatGPT，继续上传项目。当前插件如果没有 Pages 设置接口，首次启用 Pages 仍需要按第 7 步手动完成。

## 本地预览

多文件版需要通过 HTTP/HTTPS 访问，直接双击 `index.html` 的 file:// 方式不能正常加载资源。

电脑安装 Python 后，在项目文件夹打开终端并运行：

```sh
python -m http.server 8000
```

然后访问 <http://localhost:8000/>。

## 修改与更新

- 改界面文字或结构：修改 `index.html`。
- 改外观：修改 `css` 中的样式。
- 改游戏逻辑：修改 `js/app.js`，保留引用路径。
- 更新完成后上传同路径的文件并提交，Pages 会重新发布。
- `assets/charts/*.bin` 保留原文件的压缩谱面格式，不能作为普通文本直接编辑；可使用游戏原有的谱面导入功能。
- 音乐和曲绘保持原始数据，没有重新编码或降低清晰度。
- 存档、导入谱面和已保存视频仍使用原有浏览器本地存储。换设备不会自动同步这些本地数据。
- 原 HTML 的授权及来源说明已保留。拆分本身没有改变资源的授权状态。
